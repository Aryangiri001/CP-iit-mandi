# Final Submission

This is the actual hand-in format for the programme — it governs *where and
how* you submit. It does not replace the deliverables described in
[README.md](README.md) and [RUBRIC.md](RUBRIC.md); everything you build in
your project folder (SQL, notebook, dashboard, memo, AI appendix,
limitations section) still has to exist. This page just tells you how to
package and hand it in.

Every participant (individual or team) submits exactly **three items**.

## 1. Drive link

A single Google Drive folder containing **all** project files: source code,
dataset(s), the dashboard, the report, everything.

- Set sharing to **"Anyone with the link can view"** before you submit —
  test this yourself in an incognito window, don't assume it's set correctly.
- If a dataset is too large for Drive, put a text file in its place with the
  source link and instructions to reproduce it — don't just omit it silently.

Suggested folder structure inside the Drive folder (mirrors this repo, so
you can literally zip/upload your project folder as-is):

```
<YourName_or_TeamName>_<ProjectName>/
  README.md                 <- non-technical overview: question, data, approach, findings, limitations
  data/                     <- dataset(s), or a data_source.txt with the link if too large
  sql/                      <- schema + analysis queries
  notebooks/                <- cleaning, EDA, modelling notebook
  dashboard/                <- screenshots/export + the public Tableau (or equivalent) link
  memo/                     <- the one/two-page report (this is also your Report PDF, see item 3)
  ai_appendix/              <- prompt log + AI workflow appendix
```

## 2. Zoom Recording Video Link

A link to your project demonstration video, **5–10 minutes**.

- Must be publicly accessible, or set to "Anyone with the link can view."
- Cover, in order: the business question → your approach at a glance → a
  live walkthrough of the dashboard → your top finding(s) → your
  recommendation → one honest limitation.
- Business impact first, methodology second. Lead with the "so what," not
  a tour of your code.
- Record in your own voice — this is the one artifact that can't be
  copy-pasted, and reviewers weight it accordingly.

## 3. Report / Presentation Slides (PDF)

A **1–2 page** project report, or an equivalently short slide deck,
submitted as a PDF.

- Content = your decision memo: the question, the headline finding, your
  recommendation with evidence, trade-offs, and limitations.
- If you present slides instead of a memo, keep it to roughly one slide per
  section — question, approach, key finding(s), recommendation,
  limitations. Don't pad it to look more substantial than it is; a sharp
  one-pager reads better than a padded five-pager.

## Submission checklist

- [ ] Drive folder contains: source code, dataset(s) or a source note, dashboard evidence, report PDF, AI appendix, README
- [ ] Drive folder permission set to "Anyone with the link can view" — verified in an incognito window
- [ ] Zoom video is 5–10 minutes, in your own voice, link is public — verified in an incognito window
- [ ] Report/slides PDF is 1–2 pages, not longer
- [ ] All three links tested from a browser where you are **not** logged into your own Google account, to confirm reviewers can actually open them
